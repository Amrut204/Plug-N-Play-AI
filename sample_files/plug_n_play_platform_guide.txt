1. PLATFORM OVERVIEW & CORE ARCHITECTURAL PHILOSOPHY
================================================================================
Plug-N-Play AI is an enterprise-grade AI data layer and autonomous agent orchestration platform. It allows businesses, developers, universities, and organizations to connect their private databases, unstructured documents, and web services to AI assistants and deploy embeddable widgets onto any website or web application in under five minutes.

Core Architectural Pillars:
1. "Bring AI to your data, never your data to an external black box":
   - You do not need to export, migrate, or rebuild your databases. Plug-N-Play AI bridges directly to your existing systems.
2. Dual-Engine Retrieval (Unstructured RAG + Structured Text-to-SQL):
   - Typical chatbots only perform document search (RAG) and cannot query live relational databases. Plug-N-Play AI unifies both: an agent can look up policies in a PDF and query live order status in PostgreSQL in the exact same conversation!
3. Non-Negotiable Zero Database Write Mandate:
   - The platform never modifies, updates, inserts, or deletes records. Destructive queries are mathematically blocked at the Abstract Syntax Tree (AST) level before touching your database.
4. Cryptographic Multi-Tenant Isolation:
   - Every workspace is isolated by a unique Tenant UUID. No tenant can ever access, search, or view another tenant's documents, databases, vector embeddings, or chat histories.

2. THE AGENT STUDIO & CREATION WIZARD (STEP-BY-STEP)
================================================================================
The Agent Studio guides you through creating an autonomous AI agent in 4 simple steps:

STEP 1: AGENT IDENTITY & ROLE
- Agent Name: The display name visible to your visitors in the widget header (e.g., "Acme Store Concierge", "Campus Academic Advisor", "Plug-N-Play Platform Guide").

STEP 3: AUDIENCE GUARDRAILS & PERMISSIONS
- Select your target audience boundary preset:
  - End-User / Customer: Strict Row Isolation (`WHERE user_id = :id`). Prevents exposing other users' private data.
  - Internal Staff / Support: Team-level query access with sensitive column masking.
  - Executive / Admin: High-level cross-departmental reporting.

STEP 4: LIVE HUMAN ESCALATION & ACTIONS
- Configure alert channels (Direct Email, Slack/Discord Webhooks, or In-Widget Contact Cards) to notify human managers when a user requests live support.
- Configure Action Webhooks or Ambient Browser Relays for automated task execution.

3. DEEP-DIVE: DATABASE INTEGRATION ARCHITECTURES & MULTIPLE DB URLS
================================================================================
One of the most powerful and unique features of Plug-N-Play AI is its operational database query engine.

--------------------------------------------------------------------------------
A. WHY IS THERE AN OPTION TO ADD ANOTHER DATABASE (DATABASE #1, DATABASE #2)?
--------------------------------------------------------------------------------
In modern software architectures, organizations rarely keep all their data in a single monolithic database. Plug-N-Play AI supports MULTI-DATABASE FEDERATION out of the box:

Why clients use multiple database cards:
1. Cross-Domain Data Federation:
   - Example (E-Commerce):
     * Database #1: PostgreSQL containing `orders`, `customers`, and `shipping_tracking`.
     * Database #2: MySQL containing `inventory_catalog`, `warehouse_stock`, and `suppliers`.
     * The AI agent can answer: "Is my order #4012 delayed due to warehouse stock?" by querying Database #1 for the order items and Database #2 for warehouse status in a single unified response!
2. University & College Administration:
   - Database #1: Student Information System (SIS) for attendance and course enrollments.
   - Database #2: Bursar & Finance DB for tuition fees, scholarships, and outstanding balances.
3. Microservices Architecture:
   - If your application separates user accounts (Auth DB) from billing (Payments DB), you can add both databases to one agent so it has holistic context.
4. Read-Replica Splitting:
   - Direct high-frequency analytics to an AWS Aurora read replica while querying a transactional database for recent records.

If you only have one database, you simply use Database #1 and ignore the "+ Add Another Database" button!

--------------------------------------------------------------------------------
B. DIRECT CLOUD CONNECT VS. ZERO-KNOWLEDGE SCHEMA MODE
--------------------------------------------------------------------------------
Plug-N-Play AI offers two distinct connection architectures depending on your security preferences:

1. DIRECT CLOUD CONNECT MODE (Default):
   - How it works: You paste your database connection string (URL) and click "Test & Discover".
   - The platform auto-introspects your database schema, lists all public tables, and lets you check/uncheck which tables the agent is allowed to see.
   - When a visitor asks a question, the agent translates the question into a safe `SELECT` query, executes it over an encrypted SSL connection, and formats the result into natural language.
   - Best for: Cloud-hosted databases (Neon, Supabase, AWS RDS, Render PostgreSQL, DigitalOcean, PlanetScale) where you want automatic real-time queries.
   - Security Recommendation: Create a dedicated read-only user (e.g. `CREATE USER pnp_readonly WITH PASSWORD '...'`, `GRANT SELECT ON ALL TABLES IN SCHEMA public TO pnp_readonly;`).

2. ZERO-KNOWLEDGE SCHEMA ONLY MODE:
   - How it works: If your database is behind a corporate VPC, on-premise firewall, or strict compliance rules prevent sharing live database credentials, YOU NEVER PROVIDE YOUR DATABASE URL OR PASSWORD!
   - Instead, you simply paste your SQL DDL schema (e.g. `CREATE TABLE orders (...)`, Prisma schema, or JSON schema).
   - When a visitor asks a question, the AI generates the exact SQL query against your schema structure.
   - Your local application receives the query via our SDK/API or Connector Bridge, executes it locally behind your firewall, and returns only the query result to the agent.
   - Best for: Banks, healthcare providers, local offline databases, and privacy-sensitive enterprises.

--------------------------------------------------------------------------------
C. SUPPORTED DATABASE ENGINES & CONNECTION URL FORMATS
--------------------------------------------------------------------------------
Plug-N-Play AI automatically normalizes and supports all standard database connection formats:

1. PostgreSQL:
   - Standard: `postgresql://user:password@host:port/dbname?sslmode=require`
   - SQLAlchemy / Neon format: `postgresql+asyncpg://user:password@host:port/dbname?ssl=require`
   - Supabase / AWS RDS: Supports pooled and direct connection strings with SSL.
2. MySQL & MariaDB:
   - Standard: `mysql://user:password@host:3306/dbname`
   - Async formats: `mysql+aiomysql://...`, `mysql+pymysql://...`
3. MongoDB (NoSQL):
   - Standard: `mongodb://user:password@host:27017/dbname`
   - Cloud Atlas SRV: `mongodb+srv://user:password@cluster.mongodb.net/dbname`
   - For MongoDB, the engine translates queries into MongoDB aggregation pipelines with automatic `$limit` protections.
4. SQLite (Testing & Local):
   - `sqlite:///path/to/database.db`

--------------------------------------------------------------------------------
D. AST SQL SYNTAX SAFETY ENGINE (HOW WE PREVENT HACKS & CORRUPTION)
--------------------------------------------------------------------------------
Can a malicious user trick the AI into dropping or altering your database?
NO. Plug-N-Play AI features an Abstract Syntax Tree (AST) Security Gate:
- Abstract Syntax Tree (AST) Validation: Before any generated query is sent to the database, it is compiled into an AST syntax tree and validated against strict rules.
- Whitelist Only: Only pure `SELECT` queries are permitted.
- Destructive Keyword Rejection: Any query containing `DROP`, `DELETE`, `UPDATE`, `INSERT`, `ALTER`, `TRUNCATE`, `GRANT`, `REVOKE`, or `EXEC` is rejected immediately with a security alert logged.
- Semicolon Chaining Blocked: Attackers cannot append destructive chained commands with semicolons. Multi-statement executions are rejected.
- Comment Stripping: SQL injection comments (`--`, `/* */`) are forbidden.
- Sensitive Column Masking: Password hashes, salt tokens, social security numbers, and private keys are filtered out of LLM contexts automatically.
- Self-Healing Retries: If a query has a minor syntax mistake or column typo, the engine reflects the schema back to the LLM and self-corrects up to 3 times automatically.

4. DEEP-DIVE: KNOWLEDGE BASE INGESTION (UNSTRUCTURED RAG)
================================================================================
The Knowledge Base allows agents to read unstructured company documents to answer questions.

- Supported File Types: PDF (.pdf), Plain Text (.txt), Markdown (.md), CSV (.csv), JSON (.json), Microsoft Word (.docx), and Excel (.xlsx, .xls).
- Ingestion Pipeline:
  1. Document Parsing: Extracts text and tabular records cleanly.
  2. Overlapping Semantic Windows: Splits documents into 500-character chunks with a 100-character overlap, ensuring context is never lost across sentence boundaries.
  3. High-Dimensional Vector Embeddings: Embedded using 384-dimensional dense vectors.
  4. Hybrid Cosine Retrieval: Compares user queries against vector embeddings, pulling the top most relevant passages and injecting them into the prompt.
- Anti-Hallucination Scope Handling:
  If a user asks about something not contained in the knowledge base, the agent does NOT guess, apologize, or make up facts. It states:
  "I don't have that information on file currently. Please click 'Support' below to connect with our team."

5. DEEP-DIVE: ACTION AGENTS & AMBIENT BROWSER ACTION RELAYS
================================================================================
Unlike passive chatbots that only talk, Plug-N-Play AI agents can TAKE ACTION on your website.

1. Ambient Browser Relays:
   - What it is: The agent can execute client-side UI actions directly inside the visitor's browser session.
   - Examples: Adding items to an e-commerce shopping cart, navigating to a checkout page, opening a specific setting modal, or pre-filling a form.
   - Security Advantage: It runs using the visitor's existing session cookies and CSRF tokens in their browser! You do not need to share administrative API keys or master credentials with the AI.
2. External API Webhook Triggers:
   - The agent can dispatch authenticated HTTP `POST` or `GET` webhooks to your backend when certain conditions or customer intents are met (e.g., creating a support ticket in Zendesk or canceling an order in Shopify).

6. DEEP-DIVE: AUDIENCE GUARDRAILS & DATA BOUNDARY PRESETS
================================================================================
When creating an agent, you select an Audience Boundary Preset in Step 3:
1. End-User / Customer (Strict Row Isolation):
   - Appends `WHERE user_id = :authenticated_user_id` to all database lookups.
   - Prevents one customer from ever seeing another customer's order history, personal address, grades, or medical records.
2. Internal Staff / Customer Support:
   - Permits broad operational lookups while masking highly sensitive columns (like encrypted passwords and billing CVV codes).
3. Executive / Management:
   - Allows aggregate business queries (e.g. "What was our total revenue this week?").

8. UNIVERSAL WIDGET EMBED & FRAMEWORK INTEGRATION GUIDE
================================================================================
Deploying an agent to any website requires a single HTML `<script>` tag.

Universal Embed Snippet:
```html
<script 
  src="https://plug-n-play-rag.onrender.com/static/widget.js" 
  data-agent-id="YOUR_AGENT_ID" 
  async>
</script>
```

Framework Integration Examples:
1. HTML, WordPress & Shopify:
   - Paste the snippet right before the closing `</body>` tag (e.g. in `footer.php` or `theme.liquid`).
2. React (TSX / JSX):
   - Place in `public/index.html` or inject in `useEffect()`:
   ```javascript
   useEffect(() => {
     const s = document.createElement('script');
     s.src = "https://plug-n-play-rag.onrender.com/static/widget.js";
     s.setAttribute('data-agent-id', 'YOUR_AGENT_ID');
     s.async = true;
     document.body.appendChild(s);
   }, []);
   ```
3. Next.js (App Router):
   ```tsx
   import Script from 'next/script';
   <Script 
     src="https://plug-n-play-rag.onrender.com/static/widget.js" 
     data-agent-id="YOUR_AGENT_ID" 
     strategy="afterInteractive" 
   />
   ```
4. Angular: Add script URL to `angular.json` under `"scripts": []`.
5. Vue 3 & Nuxt 3: Add in `App.vue` `onMounted()` or `nuxt.config.ts`.
6. Programmatic Server-to-Server API:
   - Call `POST https://plug-n-play-rag.onrender.com/api/v1/chat/query`
   - Headers: `{"Content-Type": "application/json", "Authorization": "Bearer YOUR_MASTER_API_KEY"}`
   - Body: `{"agent_id": "YOUR_AGENT_ID", "query": "Your question here"}`

Custom Widget Attributes:
- `data-theme="dark"` or `"light"`: Forces dark or light mode.
- `data-accent="#38bdf8"`: Customizes brand theme color.
- `data-position="bottom-right"` or `"bottom-left"`: Controls widget placement.
- `data-user-id="USER_123"`: Injects active user ID for row-level security.
- `data-user-role="student"`: Injects role for role-based document access.

10. COMPREHENSIVE CLIENT FAQ & TROUBLESHOOTING DIRECTORY (Q&A)
================================================================================
Q: What is the purpose of the "Add Another Database" option?
A: It enables Multi-Database Federation! Modern businesses frequently store customer orders in one database (e.g., PostgreSQL) and warehouse inventory in another (e.g., MySQL). Adding multiple databases allows your AI agent to query across both databases simultaneously in a single conversational turn. If you only have one database, you simply fill in Database #1 and ignore the extra card.

Q: What if I only have one database? Do I need to fill in both?
A: No. If you have only one database, configure Database #1. The second database card is completely optional and can be left blank or removed.

Q: Can I connect different database engines at the same time?
A: Yes! For example, Database #1 can be PostgreSQL and Database #2 can be MySQL or MongoDB. The AI's dual-engine orchestrator parses table schemas from each connection and generates the appropriate dialect automatically.

Q: How does the AI agent know which database to query?
A: During ingestion, the platform introspects the table schemas of all connected databases. When a visitor asks a question, the orchestrator inspects which tables contain the relevant attributes (e.g., orders vs. inventory) and dispatches queries to the appropriate database.

Q: What is the difference between Direct Cloud Connect and Zero-Knowledge Schema mode?
A: Direct Cloud Connect connects directly to your database over an encrypted SSL connection to run real-time SELECT queries. Zero-Knowledge Schema mode is for organizations that cannot share their database credentials; you only paste your SQL DDL schema, and the AI outputs the exact query for your local backend to run behind your private firewall.

Q: Can the AI agent delete, alter, or drop tables in my database?
A: No. Plug-N-Play AI has an AST SQL validator that intercepts and rejects all DROP, DELETE, UPDATE, INSERT, ALTER, and destructive operations before they ever touch your database. Only safe SELECT statements are executed.

Q: What connection strings are supported for PostgreSQL?
A: Both standard postgresql://user:pass@host:port/db?sslmode=require and SQLAlchemy / Neon async format postgresql+asyncpg://user:pass@host:port/db?ssl=require. The system automatically normalizes them.

Q: Why do I experience a 2–4 second delay when testing a Neon database?
A: Serverless databases like Neon spin down to sleep when idle. When the AI sends a query, the database takes 2–4 seconds to cold-start. Our connector includes automatic retries and extended timeouts (7.0s) to handle serverless cold starts seamlessly.

Q: What should I put in the "Live Human Escalation" email section?
A: Enter your personal or support email (e.g. support@yourcompany.com). When a customer says "I want to talk to a human" or clicks the Support button, a detailed summary and conversation transcript is emailed to that address immediately.

Q: Why did my agent say "I don't have that information on file currently"?
A: Plug-N-Play AI agents have strict anti-hallucination guardrails. If a question cannot be answered from the uploaded documents or database records, the agent will never guess or hallucinate. To teach the agent new information, upload the document (or click the template chip) in Step 2 of the Agent Studio and republish.

Q: Can I embed the chatbot on my WordPress or Shopify site?
A: Yes! Simply copy the <script> tag from the Agent Studio and paste it before the closing </body> tag in your WordPress footer.php or Shopify theme.liquid. The widget will appear immediately.

Q: Can the agent execute actions like adding products to cart?
A: Yes! Using our Ambient Browser Relays, the agent can trigger client-side actions inside the visitor's browser using their existing session cookies and CSRF tokens without exposing server secrets.

Q: Which LLM models power the platform?
A: Ultra-fast inference is provided by Groq, supporting LLaMA 3.3 70B, Qwen 2.5 32B, DeepSeek R1 distillation, and OpenAI-compatible endpoints with automatic high-availability failover.

Q: Is my company's proprietary data used to train public AI models?
A: Never. All customer data and vector embeddings are cryptographically segregated by Tenant ID and never sent to third-party public models for retraining.

Q: How do I edit my profile or log out?
A: In the top navigation bar, click your profile avatar to view your account details in read-only mode. Click "Edit Profile" to modify your name or company, or click "Logout" in the top bar or modal footer to sign out securely.

Q: Is the platform free for client testing and integration?
A: Yes. Every workspace has access to the Client Testing Free Tier, which includes full Agent Studio capabilities, RAG document ingestion, direct database querying, and unlimited widget embeds.

Q: What is our workspace name or company name?
A: Our platform and company name is Plug-N-Play AI (https://plug-n-play-rag.onrender.com). For custom agents created for your business, your workspace name is the project or company name specified during setup in the Agent Studio. You can view or update your company and workspace details at any time in the Account Center by clicking your profile avatar in the navigation bar.
